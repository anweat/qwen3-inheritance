# Qwen3 结构与功能溯源实验

2026-11-05，全部在 Mac（MPS，float32）上运行。激活和因果实验只做了 0.6B 族：`Qwen3-0.6B-Base`、`Qwen3-0.6B`、`Qwen3-ASR-0.6B`。权重分析覆盖 0.6B 和 1.7B 两族。脚本和原始输出在 `experiments/e1_block_atlas/`、`experiments/e2_activation/`。

## 结论

1. **2-bit 残差在模拟中有条件地成立，但在真实端侧运行时上不划算（第九节）。**
   - **模拟（fp32 torch）。** 指定语言后，它和对称 Q4 差不多；自动检测语言时没有通过。
   - **真实内核（2026-11-08，M4 + MLX，预设标准）。** 相对 MLX 原生仿射 Q4，准确率差 +1.3 [+0.7, +1.9] 个百分点，端到端慢约 34%，两项都未通过。原因是真实的 Q4 基准比模拟时的强。
   - **代价换来的。** 计入缩放后，残差是 2.5–3 bit 而不是 2 bit，LLM + ASR 只省约 110 MB。
   - **按语言看。** 中文和方言上准确率仍然持平。
   - **其他限制。** 1-bit 不行，embedding 不能这样压，TTS 不适用。
2. **ASR 的漂移确实承载功能，不是随机扩散。** 把残差换成同范数噪声，错误率到 100%。
3. **Qwen3 有一个因果上很关键的结构：首 token 尖峰加注意力汇。** 去掉尖峰，CE 翻倍；保留首 token 时，64 token 注意力窗口几乎无损。这对端侧 KV 内存有直接意义。
4. **存在任务专属神经元，且出现双重分离。** 每层约 30 个神经元决定 ASR 能否开始转写，却不影响普通文本。
5. **动得最少的神经元最关键，但这不能用来省比特。** 按重要性分配比特的方案输给了均匀 2-bit。
6. **TTS 的共通结构没有通过因果检验（第十节第 2 步）。** 用线性映射把 LLM 状态接进 TTS，恢复的文本作用很小，而且还不如只接 LLM 的 embedding。同样的方法在两个 TTS 之间可以恢复 0.93–0.97，所以问题不在方法。目前没有证据表明 TTS 继承到了 LLM 的上下文处理。非线性适配还没有测试。
7. **LLM 比 TTS 文本路径更能分辨多音字，也并非不懂发音（第十节第 3 步）。** 线性探针上，LLM 的少数读音召回约 .83，TTS 文本路径约 .74–.75，差值的区间不含零。但只用近邻 5 个 token 的 embedding 就有 .77，增益在 L8 前后基本到位。
8. **多音字适配器有空间，端到端可行，但主要增益来自“读音头 + 接口”，不来自 LLM（第十节第 4 步）。** 难题集的少数读音，TTS 实际只读对约一半（0.6B .515，1.7B .470），低于预设门槛。不用换字、只写入一个读音向量，就能控制 TTS 的发音（平衡准确率 .977）。接上读音头后，在实际合成的音频上，少数读音从 .41 升到约 .80。只用 TTS 自身 L6 的读音头就能拿到 +23 个百分点，LLM L8 为 +29，继承带来的增益约 6 个百分点。检测器的真人阳性对照没有过预设线（.816 对 .90），但一名听者的盲听在 TTS 音频上支持了它的二选一判断（答出的 30 句全部一致）；同一盲听还发现 36 句中有 6 句两个读音都不像，所以实际读对率可能更低。改读后的音频还没有人听过，日常文本的误伤风险也还没有排除。
9. **独立 ASR 评委组只在声韵不同的对比上成立（第十节第 5 步）。** SenseVoice、Paraformer、Whisper 在 TTS 和真人音频上都过了预设线；只差声调的对比没有评委在真人上达到 .90，也没有评委能可靠报告第三种读音。不居中的 Charsiu 在真人上声韵判对 .951，是声调和第三读音的候选，但这是看过结果后才发现的，需要新的真人数据复核。
10. **直接让 LLM 判断读音没有用（第十节第 6 步）。** 零样本提示下，Qwen3-0.6B/1.7B/4B 在少数读音上只有 .46–.48，低于 TTS 自己，也低于在隐藏状态上训练的读音头（.75–.77），规模变大不见改善；4B 思考模式（探索性）是 .517，也只和 TTS 持平。LLM 懂词义，读音却常常记反。所以能用的接口是在隐藏状态上接一个有监督的窄读音头，而不是让 LLM 用文字告诉 TTS 怎么读。
11. **监督式 G2P 比 LLM 读音头更好（第十节第 7 步）。** 在 CPP 上重训的 g2pW 官方测试集达到 .990。在同一批少数读音上，它比 LLM L8 读音头高 .126 [+.073, +.186]。经读音码本接入 TTS 后，端到端从 .41 提到 .87，在 natural2 上也安全。LLM 读音头没有超过 g2pW，两者错误也几乎不互补。所以在这个试点任务上，有价值的是读音码本接口，而不是 LLM 的知识。
12. **端侧读音管线可用（第十节第 8 步）。** 管线是 g2pW int8（114 MB，每句 39 ms）→ 读音码本 → 不改动的 TTS-0.6B，句中所有可改写的多音字都改，另加用户词典。
    - 检测器的预设判定：有用，也安全。少数读音从 .522 到 .848，提升 +.326 [+.209, +.447]；natural2 从 .794 到 .916，提升 +.122 [+.034, +.221]。
    - 三评委复核：少数读音 +.344 [+.192, +.497]，与检测器一致；natural2 +.059 [−.060, +.206]，区间含零。
    - 被改写的目标 .800 → .978，未改写的目标 .913 → .739（探索性）。
    - 用新样本做的对照：预设判定不确定（−.125 [−.266, +.011]），但伤害集中在同词邻字被改写的情况（2 字以内 −.232，更远为 0）。
    - 词级规则 v2（同一词里有多音字不能改写，就不改这个词）：变化句上三评委 +.227 [.000, +.360]，7 句变好、0 句变差，但只来自“番”“长”两个字，下界不大于 0，预设的修复判据未过，所以不替换 v1。v2 在其他集合上与 v1 持平，少数读音增益完全保留。
    - 词典演示 21 句全部读对。
    - 改读后的音频还没有多人听测。码本只覆盖 650 个读音中的 407 个。
13. **其他模型族的 TTS 也像是浅层共享、深层分化，但没有证实（第十节第 9 步）。**
    - 权重：Llasa-1B 来自 Llama-3.2-1B（余弦 .66），Spark-TTS 来自 Qwen2.5-0.5B（.20），CosyVoice2 的 LM 来自 Qwen2-0.5B-Instruct（.31，不是常说的 Qwen2.5）。
    - 表示：三者的 CKA 都从浅层 .37–.56 降到深层约 .2，接近随机对照，和 Qwen3 的 TTS 一样。
    - 线性 CKA 受大激活影响，处理后同家族正对照仍未全部过 .9，所以预设判定为“测量无效”。

## 一、Qwen3 的结构

**参数预算。** 0.6B 每层约 1570 万参数，MLP 占 60%，注意力占 40%。28 层加 1.56 亿 embedding，共 5.96 亿。

**首 token 尖峰（实测，Base）。** 不管第一个 token 是什么，L2 的 MLP 都会把它写成巨大的值：

| 阶段 | 发生了什么 |
|---|---|
| L2 | 神经元 55、1489、128、321、46 向第 35 维写入约 +6800 |
| L3–L26 | 该 token 几乎不再变化（MLP 输出 rms 约 0.005），流范数约 7000，普通 token 只有约 26 |
| L27 | MLP 输出 rms 跳到 168，把它抵消掉 |

Instruct 和 ASR 用的是同一批神经元（前五名相同，ASR 里顺序略有变化）。这个现象看起来就是文献里的 massive activations，本轮没有查证原文。

**注意力汇。** 落在第一个 token 上的注意力，从 L2 的 3% 上升到 L14 的 48%、L26 的 71%（均匀分布约 3.5%），L26 有 14/16 个头超过一半。

**RMSNorm。** 权重均值从 0.18（L0）涨到 14.55（L27），基本跟普通 token 的流尺度同步（L12：1.62 对 1.46；L24：10.84 对 11.53）。除 TTS-0.6B 外，其余模型都几乎原样保留，TTS-0.6B 只从 0.28 涨到 1.34。

**因果验证（Base，文本 CE）：**

| 干预 | code | en_doc | zh_doc |
|---|---|---|---|
| 完好 | 2.19 | 2.54 | 4.54 |
| 去掉尖峰 | 5.08 | 5.42 | 7.43 |
| 窗口 64，保留首 token | 2.24 | 2.57 | 4.56 |
| 窗口 64，丢弃首 token | 3.53 | 4.05 | 5.93 |
| 窗口 32，保留首 token | 2.38 | 2.79 | 4.65 |
| 窗口 16，保留首 token | 2.67 | 3.24 | 4.95 |

## 二、不同“频度”的参数分析

| 维度 | 结果 | 含义 |
|---|---|---|
| 奇异值频段 | 残差能量在 Base 各奇异频段的分布接近 iid 噪声；顶部 1% 只高出 1.5–2.5 倍 | 漂移高维、各向同性，LoRA 提取不可行 |
| 频段内相对漂移 | ASR：顶部 1% 为 0.10，底部 50% 为 0.50 | 主方向相对稳定，所以主子空间重合度高 |
| 权重幅值 | 窄微调的 Δ 与幅值基本无关；ASR 和 TTS 的 Δ 随幅值增大，含收缩成分 | 更新近似加性，叠加收缩 |
| 符号翻转 | ASR 最小 10% 的权重翻转 42%，最大的几乎不翻；TTS-0.6B 各分位都是 0.500 | 大权重符号被继承；TTS-0.6B 与 Base 无继承关系 |
| Token 频段 | 见第五节 | 能反推训练数据 |
| 神经元发放率 | 发放率中位数从 L0 的 11% 降到 L27 的 0.4%；峰度中位数从 41 升到 267 | 越深越稀疏；发放率与 \|DLA\| 相关 0.54–0.85 |
| 输出归因集中度 | L0 最高 1% 神经元占 4%，L27 占 34.5% | 输出端高度集中 |
| 时间频率 | 谱质心 0.17–0.25 cycles/token，白噪声约 0.25 | 激活接近白噪声，这个维度区分不出神经元群 |

**压缩的直接度量：Q4 编码的条件熵（比特/权重，独立存储约 3.6）。**

| 模型 | 给定 | H(W\|参考) | 节省 |
|---|---|---|---|
| Guard-Gen-0.6B | Base | 0.12 | 96.6% |
| Guard-Stream-0.6B | Instruct | 0.27 | 92.6% |
| TTS-CustomVoice-0.6B | TTS-Base | 0.26 | 92.9% |
| Reranker-0.6B | Instruct | 0.51 | 85.8% |
| VL-Embedding-2B | VL-Instruct | 0.61 | 82.9% |
| Embedding-0.6B | Base | 0.88 | 75.5% |
| ASR-1.7B | VL-Instruct | 1.81 | 49.4% |
| ASR-0.6B | Instruct | 2.25 | 37.4% |
| TTS-Base（任一尺寸） | Instruct | 3.57–3.60 | 约 0–1% |

模型构成一棵树：同一分支内距离 0.005–0.16，跨功能 0.25 以上，TTS 与其他模型约 1.4–1.5。TTS-0.6B 与 Base 余弦为 0.000，看起来是独立训练的；TTS-1.7B 从 Base 出发，几乎被重写。

## 三、权重距离不等于功能距离

同样的文本上，ASR 的权重离 Base 比 Instruct 远约 3 倍（0.34 对 0.12），输出却更接近 Base：

| 对比 | code JS | en_doc JS | zh_doc JS | code top-1 一致率 |
|---|---|---|---|---|
| Base–Instruct | 0.143 | 0.162 | 0.176 | 0.73 |
| Base–ASR | 0.056 | 0.076 | 0.097 | 0.80 |

文本上，Instruct 的真实漂移和同范数噪声影响相近（JS 0.18–0.25 对 0.15–0.18），收缩本身几乎无影响（0.001）。但在 chat 上真实漂移影响是噪声的 3 倍（0.51 对 0.17）。方向只在它训练过的领域才明显起作用。

## 四、ASR：什么是必需的

错误率为 LibriSpeech WER / say 英文 WER / say 中文 CER，上限 64 token。64 token 会截断长句，所以 LibriSpeech 基线是 0.077（128 token 时是 0.040），只应在同一设置内比较。CE 是相对完好 ASR 自身输出的 teacher-forced 值。

| 条件 | CE | 错误率 | 比特/权重 |
|---|---|---|---|
| 完好 | 0.022 | 0.077 / 0.000 / 0.029 | 原始 BF16 |
| 独立 Q4 | 0.089 | 0.078 / 0.008 / 0.032 | 4 |
| 独立 Q3 | 2.503 | 1.000 / 0.943 / 1.000 | 3 |
| **Q4 Base + 3-bit 残差** | 0.038 | 0.080 / 0.000 / 0.029 | 3（加基座） |
| **Q4 Base + 2-bit 残差** | 0.072 | 0.075 / 0.000 / 0.044 | 2（加基座） |
| Q4 Base + 1-bit 残差 | 1.831 | 1.000 / 1.000 / 1.000 | 1（加基座） |
| 残差换成同范数噪声（128 token） | — | 1.000 / 1.000 / 1.000 | — |
| 矩阵全换成 Base（128 token） | — | 1.000 / 1.000 / 1.000 | — |

Q3、Q4 残差用对称分块量化。2-bit 用的是 4 级无零点量化，我最初用的 3 级版本失败了。1-bit 是符号乘分块平均幅值。

**残差容忍度。** 保持尺度、把残差缩到 t 倍：t≥0.85 基本无损（CE ≤0.047），t=0.8 开始退化，t=0.7 彻底失败。

**单层恢复。** 只把一层换成 α·Base：L1–L26 中任意一层 CE 都只有 0.023–0.039，几乎无影响；L0（0.405）和 L27（0.414）例外。但损伤会累积：挑最不敏感的层一起退回 Q4 基座（其余层用 Q3 残差），2 层 CE 0.049，4 层错误率已明显上升（LibriSpeech 0.361），8 层完全失败。

**单一矩阵类型恢复（全部层）：** q 0.069、k 0.123、v 0.192、o 0.190、up 0.489、gate 0.637、down 2.474。`down_proj` 最关键。

**稳定核心（因果）。** 在 ASR 转写上清零每层 10% 神经元：

| 选择方式 | 错误率 |
|---|---|
| 随机 | 0.674 / 1.000 / 1.000 |
| 动得最多 | 0.064 / 0.000 / 0.132 |
| 动得最多，按 \|DLA\| 匹配 | 0.058 / 0.000 / 0.129 |
| 动得最少，按 \|DLA\| 匹配 | 1.000 / 1.000 / 1.118 |
| 动得最少 | 2.135 / 2.292 / 6.374 |

Base 的文本结果方向相同，并且在匹配 \|DLA\| 后依然成立。

**按重要性分配比特失败了。** 把动得最多的 50% 神经元设为 0 比特、其余 Q3（平均 2.10 比特）错误率 100%；均匀 2-bit（2.00 比特）基本无损。让最不敏感的层一起用 0 比特也一样失败。每一部分残差都有小而必要的贡献，尽管动得最多的部分作用确实较小。

**任务专属神经元（双重分离）。** 在 L2、L27 以外的 26 层，每层清零 1% 神经元（约 30 个）：

| 清零的神经元 | 转写前缀一致率 | 转写内容 CE | 转写结果 | 文本 CE（code） |
|---|---|---|---|---|
| 随机 | 1.000 | 0.034 | 正常 | 2.343 |
| 文本专属 | 1.000 | 0.030 | 正常 | **2.915** |
| 转写专属 | **0.128** | **0.566** | 立即结束，无输出 | 2.338 |

损伤主要落在 `language X<asr_text>` 这一步，所以它们更像“转写任务”神经元，不是单纯的“音频”神经元。它们的可塑性并不突出（可塑性与转写/文本归因比的相关只有 −0.06），所以看权重漂移找不到它们。

**音频归因。** 从 L3 起，转写时注意力大部分落在首 token（抽样层上为 45–80%）。读音频的是少数特定的头：L6、L18、L21 的单头占比可达 0.77–0.80，同层最低只有 0.01 左右。到 L27 几乎不读音频（1.2%）。

## 五、数据溯源：embedding 行漂移

embedding 与输出头绑定，所以行漂移能反映训练接触过什么。下面的 token 是相对漂移最大的一批，解读属于推断。

| 模型 | 漂移最大的 token | 推断 |
|---|---|---|
| Instruct、Guard-Stream、Reranker | `*sizeof`、`*((`、`)?;`、`------>` | 三者几乎相同（秩相关 1.000），都来自 Instruct |
| Guard-Gen | `Unsafe`、`(passport`、`.PERMISSION` | 与安全分类任务吻合，`Unsafe` 看起来是其输出标签 |
| ASR、ForcedAligner | 囡、啷、恁、伢、侪、咩 | 口语和方言用字；我记得 ASR 报告提到方言，本轮未复核 |
| Embedding-0.6B | 无 | 共有行与 Base 完全相同，embedding 被冻结 |

特殊 token（如 `<|im_start|>`）在 Instruct 中相对漂移约 1.14，普通 token 约 0.12。TTS-0.6B 的文本 embedding 宽度是 2048，无法逐行比较。

## 六、被否定的假设

| 假设 | 结果 |
|---|---|
| 大部分漂移是无功能的扩散 | 对 ASR 不成立，换成噪声后转写彻底失败 |
| 权重重尾导致 TTS-0.6B 量化敏感 | Q4 分块误差所有模型都约 0.10，不成立 |
| 按可塑性或层敏感度分配比特更省 | 输给均匀 2-bit |
| 时间频率能区分神经元群 | 接近白噪声，区分不出 |
| 动得多的神经元就是功能专属的 | 相关约 −0.06 |

另有两个我自己的错误已修正：delta 余弦被共同的收缩项污染（TTS 与 ASR 的 0.46 其实是伪影）；恢复 Base 权重时没有配平尺度，会把激活放大到约 1.9 倍。

## 七、局限

- **语音数据少：** 30 条真实英文（LibriSpeech）、15 条合成英文、15 条合成中文。**没有真实中文或方言语音**，而社区数据显示低资源语言对 4-bit 更敏感。
- **文本语料薄：** spoken 只有 384 token，chat 只有 267 token。
- **只量化了解码器矩阵：** 音频编码器和 embedding 保持原精度。
- **选择和测试用了同一批片段：** 任务专属神经元的结果可能偏乐观。
- **只测了存储和质量：** 运行时要么合并权重（内存不省），要么同时跑基座和残差两套 GEMM（速度和内核都没测）。
- **其他：** 窗口测试上下文只有 128 token；DLA 只算直接效应，低估浅层；多数条件只跑一个随机种子；1.7B 只抽了第 14 层。

## 九、真实语音复核（2026-11-06）

留出测试集共 800 条，来自 15 个集合：AISHELL-1（100 条）、MagicData 五种方言、FLEURS 九种语言（各 50 条）。全部在 Mac 上运行，脚本和逐条结果在 `experiments/e3_real_speech/`。只量化解码器矩阵。

### 真实内核复核（2026-11-08，Mac M4，MLX）

**为什么要补这一步。** 上面的结果都是在 fp32 torch 里模拟量化：对称 Q4、Lloyd-Max 2-bit，每组缩放的存储没有计入，运行时开销也没有测。这次把 Qwen3-ASR-0.6B 的文本解码器搬到 MLX 上，用打包好的权重和 `mx.quantized_matmul` 跑。

**做法。**
- **共用部分。** 音频塔输出和提示（语言按 E3 指定）由 `prep.py` 一次算好，所有方案共用。embedding、lm_head、norm 在所有方案里都保持 bf16。
- **五个方案**：完好 bf16；MLX 原生仿射 Q4（每组 32 或 64）；Instruct 的同款 Q4 作共享底座，加 2-bit 残差（每组 32 或 64）。
- **残差的编码和运行。** 残差用均匀 4 级 midrise，步长按组最小平方误差选。运行时是两个内核：y = a·qmm4(x, 底座) + qmm2(x, 残差)，没有融合。
- **单步编译。** 解码单步的定形部分用 `mx.compile`。
- **交替执行。** 每条音频上五个方案轮换顺序执行，这样后台负载不会偏向某个方案。运行期间机器上有别的进程，负载在 4–30 之间。
- **预设标准和结果。** 标准写在 `experiments/e5_runtime/run_mlx.py` 开头，在任何方案解码之前定下。结果在 `experiments/e5_runtime/results.txt`。
- **健全性检查。** MLX 完好模型错误率 9.93%，torch 是 9.88%；90.6% 的转写逐字相同。

| 方案 | 错误率（800 条） | 中文+方言 | 其他语言 | 解码 ms/token | 端到端中位数 | ASR 专属解码器字节 |
|---|---|---|---|---|---|---|
| 完好 bf16 | 9.93% | 9.10 | 10.69 | 14.1 | 693 ms | 881 MB |
| 独立 Q4，组 32 | 11.36% | 9.14 | 13.39 | 8.3 | 526 ms | 275 MB（5.0 bit/权重） |
| 共享 Q4 + 2-bit 残差，组 32 | 12.68% | 9.20 | 15.85 | 10.6 | 707 ms | 165 MB（3.0 bit） |
| 独立 Q4，组 64 | 11.69% | 8.98 | 14.16 | 8.1 | 508 ms | 248 MB（4.5 bit） |
| 共享 Q4 + 2-bit 残差，组 64 | 13.31% | 9.07 | 17.17 | 10.4 | 704 ms | 138 MB（2.5 bit） |

**预设判定：两个组大小都没有通过。**

- **准确率：未通过。** 残差相对独立 Q4：
  - 组 32：+1.31 [+0.74, +1.88]，最差的集合是阿拉伯语 +4.2。
  - 组 64：+1.62 [+0.28, +3.19]，最差的集合是阿拉伯语 +6.7。
- **运行时：不可接受。** 端到端中位数比值 1.34（组 32）和 1.36（组 64），预设线是 ≤1.25。
  - 解码每 token 慢 1.29–1.30 倍。
  - 预填充慢 1.89 倍：两次矩阵乘，在计算受限的阶段几乎翻倍。
  - 只看解码器层的单步基准，是 1.32–1.33 倍。

**内存（只报告，不判定）。** 计入每组缩放和偏置后，残差是 3.0 bit 或 2.5 bit，不是 2 bit；独立 Q4 是 5.0 或 4.5 bit。“LLM + ASR”两份解码器矩阵：
- 组 32：从 551 MB 降到 440 MB，省 110 MB。
- 组 64：从 496 MB 降到 385 MB，省 110 MB。

如果把两份 bf16 embedding（各 311 MB）算进去，总量只少约 10%。

**探索性分析：为什么和 E3 不一样。** 主要是基准变强了，残差本身没有变差。
- 在同样的权重上，E3 模拟的对称 Q4 相对误差是 .099，MLX 仿射 Q4（带偏置）是 .082。
- 残差方案的误差，E3 Lloyd-Max 是 .116，这里均匀 2-bit 是 .113，几乎一样。
- 也就是说，E3“2-bit 残差和独立 Q4 等效”比的是一个偏弱的 Q4。换成实际运行时默认的量化器，独立 Q4 更好，残差就落后了。
- 中文和方言上仍然没有差别：+0.06 [−0.58, +0.63]。损失集中在其他语言：+2.46 [+1.56, +3.41]。

**结论：**
- 在真实端侧运行时上，“共享 LLM 底座 + ASR 2-bit 残差”不划算。它比独立 Q4 准确率差约 1.3 个百分点，端到端慢约 34%，只换来约 110 MB 的内存节省。
- 只对中文 ASR 而言准确率可以接受，但速度代价不变。
- 要让这个方案成立，至少需要两样东西：一个融合内核（一次读底座和残差，解码器理论上只多读约 60% 的字节），以及更好的残差编码。这两样都没有做。第 1 条结论需要据此修改。

## 十、任务之间有没有共通结构（2026-11-06，笔记本 GPU）

同样的文本（75 段、4800 个 token）分别过 LLM、ASR、TTS talker 和随机初始化网络，只比较文本位置。TTS 用非流式模式。脚本和原始输出在 `experiments/e4_tts_structure/`。

**表示相似度（去偏线性 CKA，相对同尺寸 Base，同深度）：**

| 模型 | L2 | L4 | L6 | L8 | L12 | L16 | L20 | L26 |
|---|---|---|---|---|---|---|---|---|
| ASR-0.6B | 0.98 | 0.97 | 0.97 | 0.92 | 0.92 | 0.96 | 0.96 | 0.95 |
| TTS-0.6B（独立训练） | **0.63** | **0.61** | **0.46** | 0.29 | 0.24 | 0.05 | 0.06 | 0.03 |
| 随机网络（对照） | 0.11 | 0.13 | 0.13 | 0.13 | 0.16 | 0.19 | 0.19 | 0.20 |
| TTS-1.7B（从 Base 出发） | **0.70** | **0.66** | **0.56** | **0.45** | **0.34** | 0.33 | 0.20 | 0.12 |
| 随机网络（对照） | 0.13 | 0.14 | 0.15 | 0.15 | 0.18 | 0.23 | 0.20 | 0.18 |

打乱 token 后 CKA 全部为 0.00。L0 的对照也有 0.40–0.46，那只反映 token 身份，不算共通结构。

**线性重建（留出段上的 R²）：**

| 方向 | L4→L4 | L8→L8 | L12→L12 | L20→L20 | L27→L27 |
|---|---|---|---|---|---|
| Base-0.6B → TTS-0.6B | 0.50 | 0.41 | 0.28 | 0.24 | 0.13 |
| TTS-0.6B → Base-0.6B | 0.40 | 0.20 | 0.14 | 0.12 | 0.12 |
| 随机 → TTS-0.6B（对照） | 0.03 | −0.08 | −0.06 | 0.03 | −0.12 |
| Base-1.7B → TTS-1.7B | 0.51 | 0.44 | 0.40 | 0.39 | 0.21 |
| TTS-1.7B → Base-1.7B | 0.38 | 0.25 | 0.21 | 0.16 | 0.13 |

对照在 TTS 深层目标上并不稳定，例如 0.6B 的 L4→L24 也有 0.23，所以深层的 R² 不能当作共通证据。

**看到的结构：**

1. **ASR 全程共享。** 文本路径上 CKA 全程 0.91–0.98，注意力也几乎一致（匹配头 JS 0.04–0.06，随机配对约 0.35–0.48）。
2. **TTS 是前段共享、后段分化。** 独立训练的 TTS-0.6B 权重余弦为 0，但前几层仍收敛到和 LLM 相近的表示，明显高于随机对照。从 L16 起 CKA 甚至低于随机网络，说明后段做的是另一件事。
3. **方向不对称。** 从 LLM 预测 TTS 比反过来准（L12：0.28 对 0.14），符合“TTS 用到的文本信息大多在 LLM 里，反之不然”。
4. **LLM 深层依然保留 TTS 前段需要的信息。** Base L20 预测 TTS L4 的 R² 是 0.42，和 L4 预测自身的 0.50 差得不多。所以分叉不一定要从浅层取，LLM 已算好的较深层也可能够用（待第 2 步验证）。**更正：第 2 步否定了这个推断，见本节末尾。**
5. **注意力汇可能是通用需求，位置可以不同。** TTS-1.7B 保留了首 token 尖峰和 L26 之前的汇。TTS-0.6B 没有 L2 尖峰，首 token 的注意力也接近 0，但在多个层上，文本 token 超过一半的注意力落在其余前缀位置（L2 约 83%）。这些位置具体是哪个还没逐一确认。
6. **注意力只是部分相似。** TTS-0.6B 的匹配头 JS 为 0.35–0.47，随机配对 0.40–0.56，优势不大，远不如 ASR。

**局限：** CKA 只说明相似，不证明可替换。线性 CKA 对重尾敏感，Instruct 在 L8、L12、L14 掉到约 0.74，而相邻层约 0.93，应该就有这个因素。语料里有代码和文档，并非 TTS 常见输入。文本位置的深层表示也可能低估共享程度，因为 TTS 的深层功能主要体现在之后的声码位置，这里没有比较。

### 第 2 步：因果拼接（线性）

**做法：** 在 talker 第 k 层覆盖文本位置，并屏蔽声码行在 k 之前读取文本，这样文本只能经由提供的状态到达音频侧。指标是真实语音上第一码本的 teacher-forced CE，共 100 条留出语音（中文、方言、英语），映射用岭回归，训练用 473 条序列。recovered = (无文本 CE − 条件 CE) / (无文本 CE − 原生 CE)，1 表示和原生文本一样好，0 表示和没有文本一样。无文本指覆盖为训练集均值。脚本：`stitch.py`、`stitch_control.py`；结果：`stitch_results.txt`、`stitch_control_results.txt`。

**TTS 只在很窄的窗口读文本。** 0.6B 的屏蔽结果和注意力占比一致。1.7B 的 L0–L2 也有 0.04–0.10 的占比，但屏蔽后 CE 并不变差，所以单看占比会高估这几层：

| 模型 | 未屏蔽 CE | 无文本 CE | 只留一层读取 | 读取层注意力占比（其余层） |
|---|---|---|---|---|
| TTS-0.6B | 1.466 | 约 2.48 | 只留 L6：1.480；L7 起无效果 | L5、L6 各 0.10（其余 ≤0.03） |
| TTS-1.7B | 1.441 | 约 2.2–2.3 | 只留 L3 及之后：1.408；L4 起只剩 2.04 | L3 0.16，L14–L17 有少量读取 |

所以 talker 基本是“文本编码 + 单点读取 + 音频解码”。文本行和音频行共用这些层，因此就算文本改由 LLM 提供，这些层也省不掉。接 LLM 能带来的只会是知识，不是参数节省。

**拼接结果（recovered）：**

| 来源 → talker 第 k 层 | 0.6B k=1 | 0.6B k=3 | 0.6B k=6 | 1.7B k=1 | 1.7B k=2 | 1.7B k=3 |
|---|---|---|---|---|---|---|
| **LLM 同深度状态** | **0.10** | **−0.03** | **0.02** | **0.30** | **0.15** | **0.01** |
| LLM embedding（只有 token 身份） | 0.14 | 0.08 | 0.01 | 0.36 | 0.27 | 0.05 |
| 另一个 TTS 同深度状态（正对照） | 0.97 | 0.93 | 0.44 | 0.85 | 0.57 | 0.07 |
| 自身前一层（正对照） | 0.99 | 0.99 | 0.47 | 0.80 | 0.86 | 0.67 |
| 自身 embedding | 0.99 | 0.95 | 0.02 | 0.80 | 0.44 | 0.07 |
| 原生文本加噪到 LLM 映射的 R² | 0.99 | 0.97 | 0.92 | 0.99 | 0.98 | 0.99 |
| 原生文本截断 PCA 到同样的 R² | 0.82 | 0.72 | 0.04 | 0.85 | 0.86 | 0.47 |
| LLM 映射的 R² | 0.63 | 0.49 | 0.43 | 0.59 | 0.53 | 0.52 |

取 LLM 更深层也没有帮助：把 J=4、12、20、27 接入 k=2、4、6，0.6B 的 recovered 都不超过 0.02；1.7B 最高 0.11，而且出现在 k=8，那里原生文本本身只能降低 0.16 的 CE，比值不稳。

**读法：**

1. **这个结构按事先定的判据不通过。** 没有哪个 k 上 LLM 接近原生。最好的是 1.7B k=1 的 0.30（CE 2.040，无文本 2.303，原生 1.416）。
2. **问题不在方法。** 同样的岭回归，在两个 TTS 之间恢复 0.93–0.97（0.6B k=1、3），而 0.6B 和 1.7B 的权重并无关系。
3. **R² 不是限制。** 把原生文本加噪到相同的 R²，几乎不受影响（≥0.92）。第一步的 CKA 和 R² 高估了可替换性，上面第 4 条推断不成立。
4. **没有看到上下文继承的迹象。** 6 个 k 中，有 5 个 LLM embedding（查表）好于 LLM 同深度状态，k=6 两者相当（0.01 对 0.02）。可恢复的那一小部分很可能只是 token 身份，而不是 LLM 的上下文处理。
5. **读取层的格式是模型私有的。** 紧贴读取层时，连另一个 TTS 也只有 0.44（0.6B）和 0.07（1.7B）。所以接口更应该放在 talker 前端，让它自己的文本层去编译。
6. **读取时不依赖文本顺序（实测）。** 在读取层输入上打乱文本顺序，CE 几乎不变（0.6B k=6：1.478 对 1.480；1.7B k=3：1.410 对 1.408），但换成别的文本会明显变差（0.6B k=6：2.571），早一层打乱也会失效（0.6B k=5：2.537）。推测是前面的层把位置写进了内容，读取时按内容寻址（推断，未单独验证）。位置确实能从内容里线性解码（R² 0.81–0.82），但 LLM 也一样（0.83–0.85），所以这不是 LLM 失败的原因。

**一个待验证的解释：** LLM embedding 映射不到 TTS，而两个 TTS 之间可以，也许是因为 TTS 的 token 表示按发音组织，LLM 按语义组织，而汉字的读音和语义关系很弱。如果成立，LLM 缺的是发音知识，而这部分用一张小表就能补上，LLM 真正可能贡献的只剩多音字这类上下文判断。**更正：第 3 步否定了“LLM 不按发音组织”，但支持了“多音字上下文”这一半，见下。**

**局限：** 只测了线性映射，所以不能排除非线性适配。CE 只看第一码本且为 teacher forcing，没有听实际音频。训练序列只有 473 条，测试 token 可能没在训练中出现过，这对从 LLM 查表的映射尤其不利，不过两个 TTS 之间的映射面对同样的覆盖率仍然成功。语料混合了中文、方言和英语，没有分语言统计。

### 第 3 步：发音探针

问题有两个：LLM 里有没有发音信息；LLM 的上下文能不能比 TTS 的文本路径更好地分辨多音字。判据在看到全量结果之前写在 `pron_probe.py` 开头。冒烟测试后改过一次：层的选择从少数读音召回改为开发集准确率，因为前者会被刷高；判据 B 也是这时加上了准确率条款。

**探针 A：留出字的拼音（岭回归，按字划分训练和测试，只用单读音字，共 14,786 字）。** 判据：LLM embedding 比随机网络高不到 5 个点，且 TTS embedding 至少两项高出 20 个点，才算“LLM 不按发音组织”。

| 模型 | 声母 | 韵母 | 声调 |
|---|---|---|---|
| 多数类 | .137 | .121 | .348 |
| 随机网络 L0 | .139 | .122 | .345 |
| LLM-0.6B L0 | .533 | .350 | .640 |
| LLM-1.7B L0 | .685 | .465 | .677 |
| TTS-0.6B L0 | .774 | .559 | .863 |
| TTS-1.7B L0 | .784 | .593 | .847 |
| TTS-0.6B L6 | .863 | .770 | .911 |
| TTS-1.7B L6 | .919 | .828 | .911 |

**判据 A 不成立。** LLM embedding 比随机网络高 23–55 个点，所以“LLM 不按发音组织”是错的。它有相当多的发音信息，但明显少于 TTS，而且随深度基本不增长。TTS-0.6B 的发音信息在 L6 见顶，之后下降（L8 .597/.460/.758，L28 .191/.162/.439），和它的文本读取窗口（L5–L6）吻合。这是一个独立的佐证。

**探针 B：CPP 多音字（单字 token，199 组字与 token 类别，测试 2,335 条）。** 每个字单独训练一个对偶岭回归，每字最多 100 条训练样本。层由开发集准确率选定。特征 `t` 只含目标位置状态，因果模型里只看到左文；`t+2` 再加两个 token 之后的状态。少数读音召回指训练集多数读音以外的那些样本。

| 方法 | 准确率 | 少数读音召回 |
|---|---|---|
| 训练集多数读音 | .766 | 0 |
| pypinyin 短语词典 | .714 | .659 |
| 随机网络 L1，t+2 | .846 | .482 |
| TTS-0.6B L6，t+2 | .912 | .749 |
| TTS-1.7B L16，t+2 | .916 | .740 |
| 近邻 5 个 token 的 LLM embedding | .932 | .769 |
| LLM-0.6B L28，t+2 | .940 | .832 |
| LLM-1.7B L16，t+2 | .943 | .835 |

LLM-0.6B（t+2）的配对差值，按字 bootstrap 的 95% 置信区间：

| 对比对象 | 准确率差 | 少数读音召回差 |
|---|---|---|
| TTS-0.6B | +2.8 [+1.8, +3.9] | +8.2 [+5.1, +11.7] |
| TTS-1.7B | +2.4 [+1.3, +3.5] | +9.2 [+5.5, +13.1] |
| 词典 | +22.6 [+17.8, +27.5] | +17.2 [+8.7, +26.0] |
| 近邻 embedding | +0.7 [−0.4, +1.9] | +6.2 [+2.6, +10.1] |
| 随机网络 | +9.3 [+7.5, +11.3] | +35.0 [+28.7, +41.8] |

**判据 B 通过。** LLM-0.6B 和 LLM-1.7B 在 t 和 t+2 两种特征上，少数读音召回都比每个 TTS 文本路径和词典高 5 个点以上，区间不含零，准确率也没有下降。逐字结果复现了上一轮的点估计。

怎么读这个结果：

1. **这是第一个 LLM 明显胜过 TTS 文本路径的证据。** 拼接实验没有看到上下文继承，这里看到了，说明 LLM 的状态确实含有 TTS 文本路径里线性读不出来的信息。
2. **大头不一定要整个 LLM。** 只把近邻 5 个 token 的 embedding 拼起来，线性读取就已经好于 TTS 的文本路径（准确率 .932，召回 .769）。LLM 的状态相对它的准确率差异不显著，只在少数读音召回上多 6 个点，也就是把漏判从 23.1% 降到 16.9%。这部分才是 transformer 层计算带来的增益，比“LLM 对 TTS”的 8–9 个点要小。
3. **增益出现得很早。** LLM-0.6B 在 L8 已有 .943/.839，右文也几乎不加分（t 为 .941/.828）。这对端侧成本有意义：可能不需要跑完 28 层。不过 L8 是看过测试曲线后才注意到的，属于探索性结果。
4. **多字 token 不需要 LLM。** 58 组、671 条测试样本里，只用 embedding 就接近解决（准确率约 .99，召回约 .95），词典 .942/.928。分词时并入了词的读音已经由 token 决定。

**局限：**

- **这一步没有测 TTS 实际读对了多少（第 4 步已补上）。** 探针只读文本行，TTS 可能在音频行上才解决读音。所以这里证明的是“LLM 里有更多可读出的信息”，不是“TTS 读错了”。这是决定适配器值不值得做的关键未知数。
- 这是有监督的逐字解码，每字最多 100 条，说明信息可以被线性读出，不说明信息能被 talker 用上。
- CPP 的样本分布不等于真实文本。623 个字经过滤剩下 199 + 58 组。多重比较没有校正。
- 层的选择用了开发集，探针超参数在冒烟后调整过。冒烟只用了小样本，全量结果出来后没有再改。

### 第 4 步：TTS 实际读音（2026-11-07，Mac 和笔记本 GPU）

第 3 步只读文本行，这一步直接听 TTS 的音频。这一步决定适配器有没有存在的空间。脚本和原始结果都在 `experiments/e4_tts_structure/`：`poly_*.py`，`poly_results.txt`，`poly_natural_results.txt`，`poly_vector_results.txt`，`poly_plugin_results.txt`，`poly_gate_results.txt`。

**方法：** 对一句含多音字 c 的 CPP 测试句（金标读音 g，竞争读音 a），合成原句 O，以及把 c 换成 g、a 单读音同音字的参照 R_g、R_a。检测器是独立的 ASR：以目标左侧文本为前缀，比较下一个 token 属于 g 或 a 的概率，再以两个参照的中点居中（`asr_centred`）。校准用第二组同音字（C_g、C_a）。判据和主检测器都在看原句分数之前定好。

**预设判定：两个模型都是“有空间”。**

| 模型 | 校准平衡准确率 | 少数读音（校正后） | 多数读音（校正后） | 阈值 T | 判定 |
|---|---|---|---|---|---|
| TTS-0.6B | .983 | .515 [.396, .629] | .723 [.607, .830] | .745 | 有空间 |
| TTS-1.7B | .983 | .470 [.354, .589] | .769 [.653, .871] | .745 | 有空间 |

n = 230 少数（77 组）、90 多数（61 组）。1.7B 没有优势。两个模型在 86.2% 的句子上判定相同，36.2% 的句子都念错。

**阳性对照：没有通过预设判据。** 用 AISHELL 和 FLEURS 的 76 处真人录音，假定真人读对，预设要求至少 90% 判为金标。

| 被测音频 | TTS-0.6B 参照 | TTS-1.7B 参照 |
|---|---|---|
| 真人录音判为金标 | .816 [.656, .982] | .803 [.626, .982] |
| TTS 原句判为金标 | .921 [.856, 1.000] | .934 [.864, 1.000] |

按判据，上表的比例可能有偏。下面几点都是**看到失败后做的探索性分析**，不改变这个判定：

- 0.6B 的 14 例错误里，10 例是只差声调且常虚化的 为，2 例是 露，真人可能真的念 lòu。
- 按对比类型拆开（0.6B）：声母韵母不同的 31 处，真人 .935，TTS .968；只差声调的 45 处，真人 .733，TTS .889。**所以只差声调的结果要打折扣。**
- 只看声母韵母不同的部分，难题集少数读音 0.6B 仍是 .538 [.386, .677]，1.7B .470 [.319, .617]，“有空间”没有被推翻。原句分数呈双峰：91.6% 的原句落在某一个参照附近，只有 8.4% 处于中间。独立的 `ce_peak` 给出相近比例（.53/.70），与主检测器一致率约 80%。
- 真人音频和参照不是同一个声音，这可能是真人分数偏低的原因之一，未验证。

**难题集不等于日常文本。** CPP 的多音字偏向生僻读音和姓氏，错得多的是 覃、茜、幢、铣、翘、蔚。自然句上：

| 样本 | 内容 | TTS-0.6B 读对率 |
|---|---|---|
| 真人录音对应的自然句 | 新闻和百科，76 处，21 字 | .921（1.7B .934） |
| CPP 测试句里的自然分布 | 百科，专名多，131 处，46 字 | .794 |
| CPP 难题集（少数读音） | 专挑少数读音 | .515 |

**读音码本：通过预设判据。** 用同一读音下所有单读音单 token 字的平均文本 embedding（排除当句参照字，缩放回成员平均范数）写入一个罕见 token，再用它替换多音字，生成代码不变。

| 模型 | 码本（V） | 换字（C） | 判定 |
|---|---|---|---|
| TTS-0.6B（111 句，44 组） | .977 [.953, .996] | .982 [.958, 1.000] | 通过 |
| TTS-1.7B（同上） | .982 [.955, 1.000] | .968 [.932, .996] | 通过 |

这个结果有点意外：文本 embedding 的方差里，读音只解释 .248，打乱后也有 .194。也就是说读音方向很弱，但平均之后足以控制发音。音频时长和音量与换字版本一致，没有明显异常。另有 29 句因为读音的成员字太少被跳过。码本 1334 × 2048，16 bit 约 5.2 MB。

**读音头对比（TTS-0.6B，相同句子）。** 判据事先写在 `poly_heads.py` 头部。

| TTS-0.6B 自身 L6 | .752 | +.230 [+.096, +.360] | .922 | +.200 [+.085, +.319] |

| LLM-0.6B L4 | .761 | +.239 [+.105, +.370] | .956 | +.233 [+.129, +.347] |
| LLM-0.6B L8 | .809 | +.287 [+.152, +.422] | .967 | +.244 [+.141, +.353] |

**端到端（实际合成的码本音频）：** 少数读音 78 句，TTS 单独 .410，接 TTS 自身 L6 为 .795（+.385 [+.203, +.558]），接 LLM L8 为 .808（+.397 [+.207, +.581]），接 LLM L12 为 .833。1.7B 从 .346 到 .782–.821（用 0.6B 的 L6 头和 LLM L8、L12 头）；1.7B 用自身 L16 头为 .692。

**LLM 继承的价值（少数读音，LLM 减 TTS 自身 L6）：** L8 +.057 [+.004, +.112]，L12 +.061 [+.014, +.113]，L4 +.009 [−.030, +.047]，L28 +.030 [−.010, +.077]。L8、L12 勉强过线，5 个层都比较过且没有校正多重比较，所以这只是偏弱的证据。

**门控与不误伤。** 真人句上不加门控的读音头点估计低于 TTS，所以加了门控：只有 ridge 分差达到阈值才干预（阈值取 CPP 开发集上精度 ≥.97 的最小分差），否则交给 TTS 自己。判据在 `poly_gate.py` 头部：自然分布样本上差值下界 > −.05 算安全，难题集少数读音上差值下界 > 0 算有用。

| 样本（TTS-0.6B） | TTS | LLM L8 门控 | 差值 | 覆盖 | TTS L6 门控 | 差值 | 覆盖 |
|---|---|---|---|---|---|---|---|
| CPP 少数（n=230） | .522 | .757 | +.235 [+.122, +.349] | .75 | .648 | +.126 [+.047, +.206] | .43 |
| CPP 多数（n=90） | .722 | .944 | +.222 [+.131, +.322] | .92 | .856 | +.133 [+.047, +.228] | .72 |

探索性：门控到相同开发集精度后，LLM L8 的覆盖明显更大。减去 TTS L6 门控，CPP 少数 +.109 [+.047, +.171]，自然分布 +.038 [+.009, +.072]。门控之后继承的价值比不门控时明显，但这个比较是看到结果后才加的。

**流式模式（TTS-0.6B，默认模式，1/3 子集，107 句配对）：** 少数读音 .494 对非流式 .545，差值 −.052 [−.169, +.046]；多数读音 .833 对 .833。没有测到可靠差异。流式有 3/114 句因音频失控被剔除，非流式 0/342。

**端侧成本（Mac M4 CPU，4 线程，float32，中位数 20 token 的句子）：**

| 路径 | 参数量 | 8 bit 约 | 每句延迟 |
|---|---|---|---|
| LLM-0.6B 前 4 层 | 218.5M | 208 MB | 36 ms |
| LLM-0.6B 前 8 层 | 281.4M | 268 MB | 84 ms |
| LLM-0.6B 前 12 层 | 344.4M | 328 MB | 129 ms |
| LLM-0.6B 全部 28 层 | 596.0M | 568 MB | 322 ms |
| TTS 自身 L6 | 0（talker 本来就在跑） | 0 | 约 0 |

LLM 的大头是 embedding 表（155M 参数），如果裁剪词表，这部分有压缩空间，未测试。逐字读音头本身估计约 2 MB（199 组，未实测）。

**怎么读这个结果：**

1. **TTS 知道的比它说出来的多。** TTS 文本行上的线性头少数读音 .752，音频实际只有 .522。信息已经在 talker 里，只是没有被用来决定读音。这解释了为什么不需要 LLM 也能拿到大部分增益。
2. **最实用的接口是“读音头 + 码本”。** 这绕开了第 2 步失败的特征拼接：不用把 LLM 状态灌进 talker，只传一个离散的读音。
3. **“继承 LLM”在这个任务上价值不大。** 约 6 个百分点，代价约 268 MB 和 84 ms，门控后价值更明显一些。如果端上已经常驻 LLM，这个代价可以共享；如果没有，TTS 自身的读音头更划算。
4. **词典解决不了。** pypinyin 相对 TTS 没有显著增益。

**盲听（2026-11-07，一名听者，TTS-0.6B 原句 36 句，探索性，未预设通过线）：** 按检测器判定和对比类型分层抽样，页面不显示判定，选项顺序随机，可选“都不像 / 听不清”。结果在 `experiments/e4_tts_structure/listening_results.txt`。

| 分层 | 句数 | 给出读音 | 与检测器一致 | 都不像 |
|---|---|---|---|---|
| 判错，声韵不同 | 14 | 11 | 11 | 3 |
| 判错，只差声调 | 6 | 6 | 6 | 0 |
| 判对，声韵不同 | 10 | 7 | 7 | 3 |
| 判对，只差声调 | 6 | 6 | 6 | 0 |
| 合计 | 36 | 30 | 30（95% CP .884–1） | 6 |

1. **在 TTS 音频上，检测器的二选一得到了人耳支持。** 只差声调的 12 句全部一致（.735–1），所以声调结果不必像真人对照显示的那样整体打折。真人录音上的对照失败仍然存在，这两件事并不矛盾：一个是真人录音，一个是 TTS 音频。
2. **新问题是第三种读音。** 6 句“都不像”全是声韵不同的对比，检测器却照样给出判断，其中 句（+6.75）和 芾（−6.80）分数还很高。对全部读音类做 ASR（`listening_third.py`，看到答案后才做）：这 6 句里 gold 和 alt 的合计份额中位数为 0，答出的 30 句为 .255；最高读音落在两者之外 6/6 对 14/30。这个证据偏弱：其中 3 句只是声调不同，声韵都不同的是 3/6 对 7/30，而且 ASR 自身也常偏向第三种读音。
3. **读对率可能被高估。** 把“都不像”算作没读对，在各分层内按听者结果重新加权，少数读音从 .522 降到约 .411，多数读音从 .722 降到约 .566（未校正的原始比例，判对且声韵不同一层只有 10 句，7/10 的区间为 .348–.933）。把“都不像”去掉则与检测器相同。无论按哪种算，“有空间”的判定都不变，只会更有空间。
4. **没有验证的部分：** 听的只是原句。读音头加码本的音频（.41 → 约 .80）还没有人听过，那个数字仍然只靠检测器。

听者能看到句子和高亮的字，可能受语境或熟悉读音影响。判错的 17 句全部选了不符合句子的读音，这说明语境没有主导判断；检测器判为较少见读音的 7 句也全部一致（.590–1），但“少见”是 CPP 内的频率，不一定等于听者的熟悉程度，熟悉度和语境混合的解释不能完全排除。只有一名听者，没有听者信度。

**局限：**

- **检测器真人阳性对照未通过预设线。** 上面的盲听支持它在 TTS 音频上的二选一判断，但只有一名听者。CPP 难题集上的生僻读音没有真人录音可对照。
- **比较不完全对称。** 读音头按标签算对错，TTS 按检测器算对错。端到端用码本音频的那组才是同一把尺，它只覆盖 111 句。门控方案没有整体重新合成，假定了约 .98 的接口保真度。
- **金标由我（Claude）手工复核 pypinyin，只有一人，没有第二标注者。** 标注在合成和读音头输出之前完成。
- **覆盖范围有限。** 只测单字 token。排除了轻声（地/de、过/guo、子/zi、了、着）、一、不、没有常用同音字的读音，所以日常文本的主要难点有一部分不在内。检测器是二选一，念成第三种读音或含糊也会被归入两者之一，盲听显示这种情况确实存在（36 句中 6 句）。
- **检测器和门控都是看过中间结果后加的。** DTW 在试验中等于随机猜，所以才加了 ASR 和 `ce_peak`（当时没有看过有意义的原句分数）。门控是看到真人句结果后加的，阈值来自开发集。多重比较都没有校正。
- 自然分布样本是百科文本，不是日常口语。只用两个参考声音，一次采样。音质没有听感或客观评测。

### 第 5 步：独立 ASR 评委组（2026-11-07，Mac）

目的：在用 ASR 做对抗挖掘或优化之前，先确认有哪些不属于 Qwen 家族的识别器可以当读音评委，避免之后只是骗过一个 ASR。通过线和组内投票规则写在 `experiments/e4_tts_structure/judge_panel.py` 开头，在任何评委打分之前定下；打分脚本为 `judge_score.py`，结果在 `judge_panel_results.txt`。

评委：Charsiu（`zh_w2v2_tiny_fc_10ms`，10 ms 帧分类，210 个带调音素，没有语言模型，用左右文本 Viterbi 对齐后给空位打全部读音的分）、SenseVoiceSmall（CTC）、Paraformer-zh（非自回归）、Whisper large-v3-turbo（mlx，左文 teacher forcing，语言先验强）。Qwen3-ASR 只作基线，不计入评委组。验证数据：TTS-0.6B 的第二同音字片段 C_g/C_a（已知读音，没有用于居中），以及 89 个真人位置 H（AISHELL 和 FLEURS，手工金标）。

| 评委 | 声韵不同：TTS 平衡 | 真人 | 只差声调：TTS 平衡 | 真人 | 最高读音：TTS 命中 / 离开两读 | 真人 |
|---|---|---|---|---|---|---|
| Charsiu | .971 | .659（n 41） | .980 | .804 | .915 / .074 | .674 / .315 |
| SenseVoice | .996 | .935（n 31）**通过** | .971 | .804 | .513 / .479 | .382 / .607 |
| Paraformer | .992 | .903（n 31）**通过** | .979 | .889 | .541 / .443 | .101 / .899 |
| Whisper | .985 | .917（n 36）**通过** | .960 | .826 | .673 / .314 | .303 / .685 |
| Qwen3-ASR（基线） | .996 | .935 | .957 | .733 | — | — |

预设判定：

1. **声韵不同的对比，评委组成立。** SenseVoice、Paraformer、Whisper 三个评委通过（要求至少两个）。真人位置样本小，区间下限只有 .74–.77。
2. **只差声调的对比，评委组不成立。** 没有评委在真人上达到 .90（最高 Paraformer .889）。TTS 音频上都在 .96 以上，所以弱点仍是真人录音，与第 4 步检测器的情况一样。
3. **没有评委能报告第三种读音。** 只有 Charsiu 在 TTS 上接近（命中 .915，离开两读 .074），但真人上命中只有 .674。其余三个评委的最高读音一半左右落在两读之外，说明它们的自由识别受语言先验支配，不能当读音标签用。
4. 评委之间在原句上的方向一致率为 .906–.947，没有一个评委和 Qwen3-ASR 特别接近，独立性大致可以接受，但这只是粗看。

探索性（看到上面的结果之后，不能让评委通过）：

- **Charsiu 不居中更好。** 预设的“以 R_g、R_a 中点居中”对有语言模型的评委必须保留（不居中时真人声韵不同的正确率：SenseVoice .516、Paraformer .742、Whisper .611、Qwen .387），但对没有语言模型的 Charsiu 有害：不居中时 TTS 为 .985/.971，真人从 .659 升到 .951（n 41），声调真人仍是 .804。它是 TTS 和第三读音上最强的候选，但真人集已经看过，要在新的真人数据上重新验证。现有清单里普通话真人片段只有约 150 条，60 条已用掉，可能需要新的真人来源。
- **5 个真人位置所有评委都判成另一读音：** 露 lu4/lou4（披露、透露）2 处、为 wei4/wei2（将为、因为）2 处、肖 xiao4/xiao1 1 处。更可能是说话人实际这么读，或金标偏字典，而不是评委错。去掉后各评委声调真人为 .786–.952（Paraformer .952），声韵为 .692–1。
- **盲听：** 30 句答出的，Charsiu、SenseVoice、Paraformer、Qwen 全部一致，Whisper 28/30。6 句“都不像”中，4 个评委在 4 句上给出相同的最高读音（峒 dong1、芾 fu3、句 gu1、桔 jue2），镐 3/4 为 gao4，轧 各不相同。其中只有 句 和 桔 声韵与两读都不同；峒、芾、镐 是某一读音的声母韵母加错误声调。所以“都不像”有一半更像是声调念错，而不是念成了别的字音。

**结论：** 后续可以用声韵不同的评委组（SenseVoice、Paraformer、Whisper，多数票）去挖掘和打分；声调和第三读音还没有可信的自动评委，只能靠人耳，或先在新的真人数据上验证不居中的 Charsiu。

**局限与偏离：** 在 Mac 上跑而不是笔记本（数据在本机，速度够）。没有用 MFA，Charsiu 自己对齐。Whisper 在两句冒烟测试后补了两 token 汉字的展开（只为覆盖率，当时没有看验证指标）。Charsiu 的 HF 卡片没有标注许可证，SenseVoice 为 “other”，都只在本地评测使用。真人集小、只有一名标注者。C_g/C_a 测的是同音替身字，不是多音字本身。

### 第 6 步：把 LLM 当语言模型直接问读音（2026-11-07，Mac）

第 4 步的读音头是在隐藏状态上训练的探针，每个字都要有标注句。这里改问：不训练，直接让 Qwen3 对话模型按语境判断读音，能不能用上它的推理和知识？提示词、候选读音（与读音头相同的类别）和通过线都写在 `experiments/e4_tts_structure/poly_prompt.py` 开头，在任何模型打分之前定下。每个候选读音按它作为回答的对数概率打分，不思考模式，零样本。主模型是 Qwen3-4B，0.6B 和 1.7B 只看规模趋势。结果在 `poly_prompt_results.txt`。

| 模型 | CPP 开发集 | CPP 少数读音 | CPP 多数读音 | natural2 |
|---|---|---|---|---|
| Qwen3-0.6B 提示 | .558 | .461 | .589 | .534 |
| Qwen3-1.7B 提示 | .564 | .478 | .644 | .496 |
| Qwen3-4B 提示 | .587 | .461 | .633 | .496 |
| TTS-0.6B 实际读音 | — | .522 | .722 | .794 |
| TTS-0.6B L6 读音头 | — | .748 | .922 | .855 |
| LLM-0.6B L8 读音头 | — | .774 | .978 | .916 |

预设判定（4B）：**不有用**（比 TTS 实际读音 −.061 [−.213, +.088]），**没有超出 TTS 自身读音头**（−.287 [−.417, −.159]），**没有超出探针**（比 LLM L8 读音头 −.313 [−.444, −.185]）。门控后的阈值高到几乎不覆盖任何条目，所以“安全”只是因为它不起作用。

为了排除打分流程本身的 bug，看到结果后检查了：logit 对位正确，预测并不集中在某个位置或某个读音上。4B 自由生成时把“我去银行取钱”的“行”答成 xíng2，说明它确实读错。

**解读：** 只要每个字有几十句标注，就能从同一个 0.6B 的隐藏状态线性读出读音（探针 .77–.81）；但不给标注、直接用语言问，模型答不对，规模到 4B 也没有改善。探针的分数里有一部分来自标注本身（只用近邻 5 个 token 的 embedding 就有 .77），所以这不能说明“知识完整地藏在模型里”，只能说明：让 LLM 用文字告诉 TTS 怎么读，这条路不通；可用的接口是在隐藏状态上接一个有监督的窄读音头。思考模式和少样本提示没有包含在预设检验里；思考模式另作探索（下文）。

**思考模式（探索性，看到上面的结果后才加，`poly_prompt_think.py`，结果在 `poly_prompt_think_results.txt`）：** Qwen3-4B 先推理再回答，贪心解码，最多 768 个 token，在 Mac 上用了 1.9 小时。共 320 条，9.1% 没写完推理，9.7% 找不到候选读音（算作错）。少数读音 .517，与 TTS 实际读音（.522）持平（−.004 [−.147, +.144]），比不思考模式高 .057 [−.087, +.198]（不显著），仍低于两个读音头 .23–.26（区间不含零）；只看有答案的 299 条也只有 .602。推理过程一般能认出词和词义，但读音记反，例如它认出“征辟”是征召的意思，却断定读 pì（应为 bì）。所以加上推理也补不上：LLM 懂词义，却不可靠地知道读音。

### 第 7 步：监督式 G2P 基线 g2pW（2026-11-08，Mac）

**做法**：用 g2pW（Chen et al., Interspeech 2022，Apache-2.0）在与读音头和提示实验完全相同的条目、相同的候选类别上评测，给出的读音不在候选类别里就算错。比较方式和通过线都写在 `experiments/e4_tts_structure/g2pw_baseline.py` 开头，在 g2pW 给任何条目打分之前定下。
- **算数的模型**：用官方 `configs/config_cpp.py` 在 CPP 训练集上重训的 g2pW（bert-base-chinese 整体微调）。配置只改了设备一行（cuda 改为 mps）。早停规则在看到第一次评估之后、任何测试条目打分之前加上：连续 5 次评估（1000 步）开发集不再提高就停。
- **训练结果**：第 800 步开发集最好，.9899；第 1800 步早停。CPP 官方测试集 .9901，论文报告 .9908，所以这个基线没有被削弱。
- **对照**：官方发布的 G2PWModel-v2-onnx 只作参考。它用台湾标准的数据训练，3.8% 的读音落在候选类别外。
- **结果文件**：`g2pw_results.txt`。

| 条目集（TTS-0.6B） | n | g2pW 重训 | TTS 实际读音 | TTS L6 读音头 | LLM L8 读音头 | g2pW 发布版 |
|---|---|---|---|---|---|---|
| CPP 少数读音 | 230 | **.900** | .522 | .748 | .774 | .561 |
| CPP 多数读音 | 90 | .967 | .722 | .922 | .978 | .778 |
| 真实语音句 | 21 | 1.000 | .952 | .857 | .857 | 1.000 |
| natural2 | 131 | **.947** | .794 | .855 | .916 | .893 |
| 端到端 CPP 少数读音（经读音码本） | 78 | **.872** | .410 | — | .795 | .487 |

**预设判定（重训版，TTS-0.6B 和 1.7B 相同）**：
- g2pW **胜过 TTS 自身读音头**：+.152 [+.100, +.214]。
- g2pW **胜过 LLM L8 读音头**：+.126 [+.073, +.186]。
- **LLM 读音头没有超过 g2pW**。
- g2pW 输出经读音码本接入 TTS，**端到端有用**：0.6B 比 TTS +.462 [+.264, +.654]，1.7B +.526 [+.341, +.703]。
- 在 natural2 上**安全**：比 TTS +.153 [+.069, +.248]。

端到端时，LLM L8 加码本比 g2pW 加码本低，1.7B 上区间不含零（[−.169, −.013]），0.6B 上区间为 [−.152, .000]。在多数读音上，LLM 读音头和 g2pW 没有差别（−.011 [−.049, +.024]）。

**发布版（参考）**：它在少数读音上明显输给两个读音头（−.19 到 −.21）。所以“读音头比现成 G2P 强”只在拿错了标准的现成模型比较时成立，换成同数据重训的模型就不成立。

**探索性**（看到结果后才算）：
- **两者的错误几乎不互补。** 在 CPP 少数读音上，g2pW 错了 23 条，其中 LLM 读音头答对的只有 5 条。两者取“谁对算谁”的上限是 .922，比 g2pW 单独只高 2 个百分点。
- **g2pW 的“错误”里有些可能是金标本身有问题。** 例如“磨砂”金标是 mo4，g2pW 和 LLM 都给 mo2；“剥片”金标 bao1，两者都给 bo1。这又说明需要第二标注者。

**不对等之处**：g2pW 用了整个 CPP 训练集，并微调了整个 BERT。读音头只是冻结状态上的岭回归，训练数据还有上限。所以这里不能说“LLM 状态按每条标注计不如 BERT”，只能说：实际可用的方案里，一个专门的 1 亿参数 G2P 比从 LLM 读出更准。

大小：g2pW ONNX 为 fp32 435 MB，未量化。LLM 前 8 层 8 bit 为 268 MB。

**结论：**
- 在多音字这个试点任务上，LLM 的知识**没有带来超过监督式 G2P 的价值**。
- 第 4 步的读音码本接口是真正有用的部分，而且它对上游是谁并不挑剔：g2pW 接上去，端到端从 .41 到 .87。
- “TTS 继承 LLM 知识”的主张在这个任务上不成立；这个任务上能成立的是“一个离散的窄接口可以修正 TTS 的读音”。

### 第 8 步：端侧读音管线 E6（2026-11-08/09，Mac M4）

**做法**：把第 7 步的结论做成可部署的管线：文本 → g2pW（CPP 重训，int8）→ 读音码本 → 不改动的 Qwen3-TTS-0.6B，另加用户词典。与第 4、7 步的区别：
- 句中**所有**满足规则的多音字都改写，不只改被评测的那个位置。
- 用量化后的 g2pW，而不是 fp32。

规则和判据写在 `experiments/e6_reading_pipeline/build_plan.py` 开头，在任何管线音频生成之前定下。

**自动改写**。某个位置同时满足下面所有条件才改写：
- 字在 CPP 多音字表里，且 g2pW 给出带调拼音。
- 不是轻声，字也不是“一”或“不”（变调）。
- 该读音在码本里有向量：至少 3 个单读音、单 token 的字读这个音。
- 这个字在句子的分词里自成一个 token。

**用户词典**：词典条目总是覆盖 g2pW 的结果，即使目标字在多字 token 里面也照样改写。

**比较对象**：P 是管线音频，O 是第 4 步里未改动句子的音频，两者按条目配对。判读用第 4 步的 ASR 检测器（以同条目的 R_g/R_a 参考为中心）。

**g2pW 量化（预设：int8 子集准确率降幅不超过 .005，且少数读音降幅不超过 .02，才用 int8）**：

| | CPP 测试 2000 句子集 | CPP 少数读音 | ONNX 大小 | 单句延迟（M4 CPU，中位 / p90） |
|---|---|---|---|---|
| fp32 | .9885 | .900 | 435 MB | 54 / 97 ms |
| int8 | .9895 | .883 | 114 MB | 39 / 71 ms |

- int8 与 fp32 的预测一致率为 .998，满足预设条件，管线采用 int8。
- 第一次测延迟得到 8.6 s/句，这个数无效：g2pw 0.1.2 把 `num_workers=0` 当成未设置，每次调用都会派生 2 个进程。修正后重测。准确率不受这个问题影响。
- TTS 部分不变，Mac 上 RTF 约 0.45。码本覆盖 CPP 650 个读音中的 407 个，其余 243 个没有足够的单读音字，不能自动改写。

**结果（检测器，`experiments/e6_reading_pipeline/results.txt`）**：

|---|---|---|---|---|---|---|---|
| CPP 少数读音 | 230 | .522 | **.848** | **+.326 [+.209, +.447]** | .94 | 2.91 | 14 / 89 |
| CPP 多数读音 | 90 | .722 | .944 | +.222 [+.120, +.333] | .97 | 2.37 | 3 / 23 |
| 真实语音句 | 76 | .921 | .934 | +.013 [−.024, +.070] | .28 | 1.13 | 1 / 2 |
| natural2 | 131 | .794 | **.916** | **+.122 [+.034, +.221]** | .84 | 3.20 | 6 / 22 |

**预设判定**：
- **有用**：CPP 少数读音的下界大于 0，通过。
- **安全**：natural2 的下界高于 −.05，通过。而且下界大于 0，即不只是没有伤害，而是有提升。

在真实语音句上，目标多数不是自成一个 token（只有 28% 被改写），因此和 TTS 单独差别不大。

**与第 7 步的关系**：第 7 步只改目标字，端到端 .872（n 78）。这里全句改写、用 int8，少数读音 .848（n 230，被改写的目标 .870）。两者口径不同，不直接相减；但全句改写没有带来明显的副作用。

**用户词典（探索性演示）**：
- 句子和读音是为这次测试写的，多为人名、地名。共 26 句，其中 4 句因找不到同音参考字被去掉，剩 21 句可评分。
- 读对率：TTS 单独 .286，只用 g2pW .524，加词典 **21/21**。
- g2pW 漏掉的主要是专名读法（单雄信、查良镛、召公、任先生、华山）和多字 token 里的字（铅山、洪洞、浚县、龟兹）。词典能直接覆盖这两类。

**限制**：
- 检测器只在两个读音之间二选一，看不到第三种读音或含糊的音节。
- P 和 O 的采样不同。
- 改读后的音频还没有人听过。

**三评委复核**（作为第二意见报告，不参与判定；`experiments/e6_reading_pipeline/judge_summary.py`，结果在 `judge_results.txt`）：
- 用第 5 步的评委组：SenseVoice、Paraformer、Whisper，取严格多数。
- 只看声韵不同的条目，因为评委组只在这类对比上成立。
- O 用旧音频的评分，P 用 E6 音频的评分，同一评委。

| 条目集 | n | TTS 单独 | 管线 | 差值 [95% CI] | 三评委都投票的行 | 首选读音落在两读音之外：TTS / 管线 |
|---|---|---|---|---|---|---|
| CPP 少数读音 | 163 | .509 | **.853** | **+.344 [+.192, +.497]** | 140 | .48 / .42 |
| CPP 多数读音 | 62 | .823 | .984 | +.161 [+.066, +.270] | 55 | .37 / .39 |
| 真实语音句 | 31 | 1.000 | 1.000 | 0 | 31 | .78 / .76 |
| natural2 | 68 | .838 | .897 | +.059 [−.060, +.206] | 63 | .61 / .56 |
| 用户词典 | 19 | .263 | 只用 g2pW .526，加词典 .947 | — | 18 | .33 / .21 |

- **CPP 上与检测器一致**：少数读音大幅提升，区间不含零。
- **natural2 上更弱**：点估计仍为正，但区间含零，下界 −.060，略低于检测器用的安全线 −.05。这一条只作为第二意见报告，预设判定仍以检测器为准。
- **按目标是否被改写拆开（探索性，看到结果后才算）**：
  - 被改写的目标（45 行）：.800 → .978，对→错 0，错→对 8。
  - 未被改写的目标（23 行）：.913 → .739，对→错 5，错→对 1。
  - 这 5 行里有 4 行的目标在多字 token 里（长子、番禺、柏楠），管线并没有动它。所以下降来自采样差异，或来自同句其他位置的改写对邻近字的影响，现在分不清。
  - 检测器在未改写目标上没有看到下降（.762 → .810，含只差声调的条目）。
  - 唯一一例改写后仍错的是“靡靡之乐”：g2pW 给 le4，金标是 yue4。
- **首选读音落在两读音之外的比例，管线没有比原句更高**：这粗略说明改读没有带来更多含糊或第三种读音。但评委组本来就不能可靠报告第三读音（第 5 步），所以这只是旁证。
- **只有两个评委投票的行**：Whisper 只能给一到两个 token 的字打分，所以少数行缺它的分数。这些行只由两个评委投票，必须两者一致才算读对。

**邻近改写对照（2026-11-10，Mac；`experiments/e6_reading_pipeline/neighbour.py`，结果在 `neighbour_results.txt`）**

目的：查清上面“未改写的目标变差”是采样噪声，还是同句其他位置的改写造成的。设计和判据在合成前写在脚本开头：
- **句子**：三个集里目标未被改写、但同句至少改写了一处的句子，共 86 句。其中声韵对比 63 句，三评委都有分数的 52 句。
- **新样本**：每句重新采样两份原句（O1、O2）和两份管线（P1、P2），管线用第 8 步完全相同的改写。第 8 步那一对样本不参与判定。
- **主判定**：三评委、三集合并，算每句 P 均值减 O 均值，按字分组 bootstrap。

| | n（字） | O | P | 差值 [95% CI] | 两次采样不一致：O1/O2 · P1/P2 · O/P |
|---|---|---|---|---|---|
| 三评委，合并 | 52（22） | .846 | .721 | −.125 [−.266, +.011] | .12 · .06 · .17 |
| 三评委，natural2 | 21（9） | .881 | .714 | −.167 [−.315, +.033] | .14 · .10 · .21 |
| 三评委，hard | 19（8） | .737 | .579 | −.158 [−.438, +.071] | .11 · .00 · .21 |
| 三评委，natural | 12（9） | .958 | .958 | 0 | .08 · .08 · .04 |
| 检测器，合并 | 61（31） | .795 | .762 | −.033 [−.119, +.032] | .05 · .05 · .07 |

- **预设判定**：
  - “邻近改写有害”未成立，上界 +.011，只略高于 0。
  - “伤害不超过 5 个百分点”也不能确认。
  - 结论是不确定，但点估计在新样本上重复了第 8 步的方向。
- **探索性（看到结果后才算）**：
  - **管线样本彼此很一致，和原句却不一致**：P1/P2 只有 .06 不一致，O/P 不一致 .17，高于 O1/O2 的 .12。这更像系统性的偏移，不像采样噪声。
  - **变差集中在“同词邻字被改写”**：最近的改写离目标 2 字以内时，平均差值 −.232（28 行）；超过 2 字时为 0（24 行）。
  - **典型例子**：
    - “番禺”里的“禺”被改写，而“番”的 pan1 没有码本向量、没有改写。合并集里番 5 例全部由对变错（O 对、P 错）。
    - “厂长”的“厂”、“长子”的“子”被改写后，“长”读回了 chang2。
  - **机制猜测**：占位符把一个词拆开了，TTS 失去词的线索，未改写的字就退回到默认读音。被改写的字本身不受影响，因为它的读音直接由向量给出。
  - **对规则的含义**：改写应当以词为单位。如果同一词里有一个多音字不能改写（没有向量，或在多字 token 里），就不要改写它的邻字；或者只在 g2pW 读音与 TTS 默认读音可能不同时才改。下一小节测试了前一种。

**词级规则 v2（2026-11-10，Mac；`build_plan.py v2`、`wordrule.py`，结果在 `wordrule_results.txt`）**

- **规则**：
  - 用 jieba 0.42.1 分词。
  - 一个 2 字以上的词里，只要有一个 CPP 多音字按 v1 不能改写（没有向量、在多字 token 里、轻声或变调），这个词里的其他自动改写就全部取消。
  - 用户词典照常生效。
- **影响面**：改写有变化的句子 hard 65、natural 5、natural2 34、词典集 3；被改写的目标 hard 311 → 290，natural2 115 → 104。邻近改写对照的 86 句里有 28 句变化。
- **音频**：改写有变化的句子各新合成一份 v2（V）；对照集那 28 句再合成两份（V1、V2），和上一小节的 P1、P2、O1、O2 比。其余句子文本不变，直接用第 8 步的管线音频。共 163 条。
- **预设判据**（合成前写在 `wordrule.py` 开头，三项全过才用 v2 替换 v1）：
  1. 修复：对照集变化句，三评委，mean(V1, V2) − mean(P1, P2) 的下界 > 0。
  2. 仍然有用：检测器，CPP 少数读音，v2 管线 − 原句的下界 > 0。
  3. 仍然安全：检测器，natural2，v2 管线 − 原句的下界 > −.05。

| | n（字） | 原句 O | v1 | v2 | v2 − v1 [95% CI] | v2 − O [95% CI] |
|---|---|---|---|---|---|---|
| 1 对照集变化句，三评委 | 22（13） | .818 | .500 | .727 | +.227 [.000, +.360] | −.091 [−.194, +.036] |
| 1 对照集变化句，检测器 | 17（13） | .706 | .618 | .706 | +.088 [.000, +.225] | 0 [−.094, +.083] |
| 2 CPP 少数读音，检测器 | 230 | .522 | .848 | .848 | 0 [−.023, +.019] | +.326 [+.213, +.445] |
| CPP 多数读音，检测器 | 90 | .722 | .944 | .956 | +.011 [0, +.035] | +.233 [+.130, +.342] |
| natural，检测器 | 76 | .921 | .934 | .934 | 0 | +.013 [−.024, +.070] |
| 3 natural2，检测器 | 131 | .794 | .916 | .908 | −.008 [−.037, +.016] | +.115 [+.019, +.216] |
| CPP 少数读音，三评委 | 163 | .509 | .853 | .853 | 0 [−.035, +.035] | +.344 [+.196, +.497] |
| natural2，三评委 | 68 | .838 | .897 | .912 | +.015 [0, +.042] | +.074 [−.044, +.212] |

- **预设判定**：修复未通过；仍然有用、仍然安全都通过。按事先的规则，**不用 v2 替换 v1**。
- **为什么修复差一点**：
  - 方向完全一致。22 句里 7 句变好、0 句变差、15 句不变。
  - 但变好的 7 句只来自两个字：“番”（番禺 4 句）和“长”（厂长、长子 3 句）。
  - 按字分组的 bootstrap 抽不到这两个字时差值就是 0，所以下界正好是 .000，不大于 0。这是样本只有 13 个字造成的，不是 v2 有反作用。
- **探索性**：
  - v2 在所有集合上都不比 v1 差（v2 − v1 的区间都含零，点估计在 −.008 到 +.015 之间）。少数读音的增益完全保留。
  - v2 只修了一部分。对照集上 v2 仍比原句低 .091（不显著）。“番禺”在 v2 里不再拆词，但“番”的 pan1 没有向量，TTS 有时仍读成 fan1（如 hard 25、187 两份样本各错一份）。要彻底修好，需要给 pan1 这类缺失读音补向量，或在用户词典里收“番禺”。
  - natural2 三评委：v1 +.059 → v2 +.074，仍不显著。

**结论（v2）**：词级规则安全，也保留了全部增益，并在“番禺”“厂长”这类同词邻字的句子上一致变好。但事先定的修复判据没有过，原因是只有两个字的证据。所以 v2 只能作为“没有坏处、可能有好处”的默认选项，不能写成已证实的修复。要确认，需要更多含同词邻字的句子（例如专门挑出缺向量多音字所在的词）。

**结论**：
- 一个可以放到端侧的读音管线成立：g2pW int8（114 MB，每句 39 ms）加读音码本，TTS 本身不改动。
- 难题集少数读音的读对率从约一半提到约 85%，检测器和三评委一致。
- 日常百科文本：检测器判为安全且有提升；三评委只看到不显著的提升。
- 被改写的字几乎全对。风险在没被改写的字上，主要出现在同一词里邻字被改写的情况，例如“番禺”的“禺”被改写后，“番”读回了 fan1。词级规则 v2 在这类句子上 7 句变好、0 句变差，其他集合不变，但预设的修复判据因为只有两个字的证据而没有通过（下界 .000）。
- 用户词典能补上 G2P 不会的专名读法。
- 还没做的：
  - 多名听者听改读后的音频。
  - 码本覆盖：243 个读音没有向量，这些读音无法自动改写。
  - 多字 token 里的多音字：真实语音句上只有 28% 的目标被改写。

### 第 9 步：其他模型族的 TTS（E7，2026-11-11，AutoDL RTX 4080 SUPER）

**问题**：Qwen3 的两个 TTS，无论是独立训练的还是从 Base 出发的，都是浅层像 LLM、深层分化。这是 Qwen3-TTS 自己的特点，还是在 LLM 上训练 TTS 的普遍规律？

**做法**：
- 换三个不同家族、语音 token 也不同的 TTS：CosyVoice2-0.5B 的 LM、Spark-TTS-0.5B、Llasa-1B。
- 先用权重核实各自的底座，再在同一语料上算逐层 CKA，判据事先写定。
- 脚本、判据和两轮原始输出在 `experiments/e7_cross_family/`（`PLAN.md`、`remote_logs/`）。

**权重：谱系查清了**

| TTS | 实际底座 | 权重余弦 | 说明 |
|---|---|---|---|
| Llasa-1B | Llama-3.2-1B | .66 | 越深改得越多（ρ +.87）；离 Base 和 Instruct 一样远，分不出是哪一个 |
| Spark-TTS | Qwen2.5-0.5B | .20 | 权重被放大、重写得很厉害 |
| CosyVoice2 LM | **Qwen2-0.5B-Instruct** | .31 | 随包附带的 CosyVoice-BlankEN 与 Qwen2-0.5B-Instruct 完全相同（残差 .000）；与 Qwen2.5-0.5B 余弦为 0。文本 embedding 几乎没动（.08） |
| 参照：Instruct 对 Base | 同家族 | .99 | Qwen2.5 和 Llama-3.2 都是 |

公开资料常说 CosyVoice2 基于 Qwen2.5-0.5B，但它的权重来自 Qwen2-0.5B-Instruct。

**表示：预设判定为“测量无效”**

- **第一轮**：线性 CKA 被大激活压垮。Llama-3.2 的 Instruct 对 Base（权重余弦 .987）在 L2–L14 只有 .03–.47；Qwen2.5 的随机对照从 L3 起全为 0。原因是 Qwen2.5 在没有 BOS 时，每段第一个文本 token 会变成注意力汇，数值极大。
- **第二轮**：每层剔除超过中位数 10 倍的 token 和维度，并新增正对照：Instruct 对 Base 每层都要 ≥ .9。剔除后随机对照恢复到 .09–.20，L3 的断崖也消失了。但正对照仍未通过：Qwen2.5 只在最后一层是 .86，其余 .97–1.00；Llama 在 L9–L13 是 .79–.87，L15 只有 .67。按预设规则，不下家族判定。
- **描述性结果**（不能当判定用）：

| TTS | 浅层 S | 深层 D | 随机对照 S |
|---|---|---|---|
| Llasa-1B | .56 | .20 | .16 |
| Spark-TTS | .37 | .19 | .11 |
| CosyVoice2（对比的是 Qwen2.5，不是它真正的底座） | .41 | .23 | .11 |

三个模型都是浅层最像 LLM，往深层单调下降，到最深几层接近随机对照。这和 Qwen3 的 TTS-0.6B、TTS-1.7B 形状一致。

**结论**：
- 权重层面，三个 TTS 都确实从某个 LLM 出发，但改动很大（余弦 .20–.66，而同家族 Instruct 对 Base 是 .99）。
- 表示层面，四个家族的形状一致，都是浅层像、深层不像。方向上支持“深层分化是普遍规律”，但测量没有通过正对照，所以不能写成已证实。
- 方法教训：跨模型比较时，线性 CKA 需要先处理大激活，而且要有同家族的正对照。Qwen3 那一轮恰好没遇到这个问题。
- 未做：CosyVoice2 对 Qwen2-0.5B-Instruct 的 CKA；因果拼接（预设只在出现“深层共享”或“居中”时才做）。
