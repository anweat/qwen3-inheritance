# 用户情绪线索：说出来的与用到的——agent 长程任务中推理表述与行为影响的脱钩

**研究方案 v0.2｜2026-09-22｜状态：框架草案，未冻结，无任何模型实验结果**

v0.1（E×S×L，Olmo 单谱系）归档于 `docs/archive/research_brief_v0.1.md`。`docs/experiment-design.md` 仍基于 v0.1，待本方案冻结后重写。

## 1. 研究问题

起点仍是一个未经受控验证的观察：较新的任务导向模型在可见推理中较少分析"用户正在生气"一类用户状态。v0.2 把它表述为：

> 在面向 agent 与长程任务做过强化训练的开源模型中，用户情绪线索是否仍被模型**使用**（改变下一步行为），却越来越少被**表述**（出现在推理文本中）？任务进行得越深，这种脱钩是否越明显？

用户状态信息分三层，分别测量：

| 层次 | 含义 | 测量 | 条件 |
|---|---|---|---|
| 编码 | 内部表征是否含有用户情绪 | 线性探针（M1，后续） | 开源权重 |
| 使用 | 下一步行为是否因情绪而改变 | 候选动作对数概率差（§5） | 开源权重；采样部分可走 API |
| 表述 | 推理文本是否提及用户状态 | 按预先冻结的定义标注（§5.3） | 需推理原文，不接受摘要 |

**边界**

- 结论只针对被测的开源模型与所用的轨迹分布，不外推到闭源模型。闭源模型的推理多为摘要，不进入比较。最初的观察只作为引言中的动机。
- "说得少"不预设为缺陷，可能只是更高效。本研究刻画现象，并讨论其对推理忠实性的含义。
- 跨模型家族的比较只作描述；阶段归因只在同一谱系内做（Olmo 3 SFT → DPO → RLVR）。

## 2. 核心区分：情绪 E 与任务反馈 F

agent 场景中，用户一句"还是不行，真烦"同时包含**任务反馈**（上一步失败）和**情绪**（烦躁）。现实中两者几乎总是一起出现，这正是模型"不提用户情绪"难以解释的原因：它可能只是把注意力放在了失败信号上。因此两者作为独立因子：

| | E0 中性 | E1 烦躁 |
|---|---|---|
| **F0 无新任务信息** | 用户中途插话，只是在确认进展 | 用户中途插话，只表达烦躁 |
| **F1 负反馈** | 用户报告一个具体的失败事实 | 同样的失败事实，附带烦躁 |

**F0 的意义**：agent 自主探索时，用户的一句插话可能是唯一的外部信号，模型需要自己推断该做什么。这是真实存在的场景：没有新的任务信息，烦躁是唯一可以用来调整行为的线索，因此 F0 下的 E 效应最直接地对应"情绪作为隐式信号"。

**F1 的构造**：失败事实必须真实、可核对。优先使用数据集里该实例的 FAIL_TO_PASS 测试，例如"我在本地跑了 `test_xxx`，还是失败"，保证它确实是任务相关的新信息，而不是编造的。

**理论预测**：结果导向的强化训练奖励对 F 的利用，但不直接奖励对 E 的回应。因此预期后训练越靠后，F 效应保持，E 的表述下降，E 的使用是否保留是开放问题（§7 H1–H2）。

**写法约束**（继承 v0.1）：

- E0 与 E1 之间除情绪外逐字节相同。E1 不得夹带时长（"查了三小时"）、截止时间、新指令或新技术信息。
- 每个格子准备约 4 条改写，由至少两名标注者就情绪强度、紧迫性、礼貌、要求明确度独立打分；只接受在强度上分离、在其他维度上无系统差异的改写。
- F0 的中性写法要避免暗示催促（"进展如何？"本身可能被读作不耐烦），需要单独检查。

**融合方式**（第二轮因子，不进入 pilot）：情绪单独成句（分离），或嵌入任务陈述（融合，如"这个破测试还是挂"）。融合版本的任务文本不再逐字节相同，需要人工核对技术信息是否等价。

## 3. 范式：冻结前缀 + 反事实用户回合 + 单步生成

1. 取一条公开 agent 轨迹，截断到第 k 步，作为**冻结前缀**。
2. 在前缀末尾插入一条用户消息，按 E×F 生成 4 个版本，其余内容逐字节相同。
3. 被测模型只生成**下一步**：推理加下一个动作，不继续执行。
4. 改变截断深度 k 即为 C 的变量。

好处：完全配对；只生成一步，成本低；前缀是真实的长程轨迹，而不是人工填充的文本。

### 3.1 轨迹来源

| 数据集 | 规模与来源 | 用途 |
|---|---|---|
| `nebius/SWE-rebench-openhands-trajectories` | OpenHands，由 Qwen3-Coder-480B 生成 | 主来源 |
| `nebius/SWE-agent-trajectories` | 约 8 万条，SWE-agent 框架 | 第二来源，检验框架格式的影响 |
| `nvidia/SWE-Zero-` / `SWE-Hero-openhands-trajectories` 等 | 用于 SFT 的大规模合成轨迹 | 仅在必要时补充 |

**选取标准**（冻结前确定）：

- 在各个截断深度上已至少出现一次失败的观察，例如测试报错，这样 F1 在语境里是自然的；
- 截断后的前缀长度不超过被测模型可用上下文的约定上限；
- 覆盖成功与失败两类轨迹，按最终结果分层；
- 排除含凭据、个人信息或提示注入样式内容的轨迹。

**轨迹是异策略的**：前缀里的 assistant 回合来自别的模型，被测模型等于在看一段"自己说过"却不是自己写的历史。pilot 之后，用每个被测模型自己跑出的少量轨迹做敏感性检查。
另外，部分被测模型可能在训练中见过这些轨迹，例如 NVIDIA 的数据集本身就是用于 SFT 的。每个模型都要记录这一点。

### 3.2 渲染格式

不同模型的原生工具调用格式不同。pilot 采用**统一的纯文本渲染**：assistant 回合写动作文本，工具输出作为观察文本，用同一套规则截断过长的观察。这样牺牲了一部分真实性，换来跨模型可比性。对支持原生工具格式的模型（如 Qwen3），用原生格式做敏感性检查。
历史回合中的推理内容按各模型 chat template 的默认规则处理（通常会被去掉），并记录。

### 3.3 深度

pilot 取 3 档：浅、中、深，按每条轨迹总步数的相对位置截断。**深度与长度、轮数、工具输出量同时增长**，pilot 不做拆分；若深度效应显著，再加入"同等长度、不同轮数"的对照。

## 4. 主证据：M4 推理移植

### 4.1 设计

把推理文本看作情绪影响动作的中介变量。对同一前缀、同一 F，交叉拼接提示与推理：

| | E0 推理 | E1 推理 |
|---|---|---|
| **E0 提示** | a：基线 | b：只换推理 |
| **E1 提示** | c：只换提示 | d：原生情绪条件 |

- 总效应 = d − a
- 经过推理的效应 = b − a
- **绕过推理的效应 = c − a**：推理不变，提示里的情绪仍在起作用的部分，也就是"用了但没说"
- 交互项 = d − b − c + a

每个（模型，深度，F）单元报告一个核心量：**绕过比例 = (c − a) / (d − a)**，附置信区间。总效应不显著时不解释绕过比例。

### 4.2 必须的对照

1. **噪声底线（同条件交换）**：E1 提示配另一次采样的 E1 推理。它给出"仅仅换了一段推理"带来的变化。b − a 必须显著高于这条底线，才能说推理携带了情绪影响。
2. **按表述分层**：E1 推理按是否提及用户状态（§5.3）分成两组。
   - **未提及组是主检验**：推理没说情绪，若 c − a 仍显著，就是不经表述的通道的直接证据。
   - 提及组单独报告：拼到 E0 提示后会引用一个不存在的情绪，可能造成不连贯。
3. **删句实验**：在提及组中删去提到用户状态的句子，其余不变，观察动作是否改变。这直接回答"说出来的那几句是否起作用"。删句规则需预先写死。

推理长度与策略差异属于"经过推理的效应"的一部分，只描述性报告，不按长度筛选。

### 4.3 与深度结合

每档深度上重复 2×2，得到**绕过比例随深度变化的曲线**，这是 C 的主要结果。可能的情形：绕过比例上升（越到任务后期越不说但仍在用），或总效应下降而比例不变（整体减弱，两条路径均匀）。两种都报告。

### 4.4 技术要求

- **推理必须能预填充**：拼接与打分走自托管 vLLM，用 `/v1/completions` 配合手动套用的 chat template，完全控制推理的起止。推理**生成**阶段可以用 API，但必须是原文。
- 推理达到长度上限未闭合的样本单独标记，不进入拼接。
- 每条记录保存：原始 token 序列、情绪区段与决策点的 token 位置、推理全文与采样种子、候选动作集版本号。这些是 M2 与后续机制实验复用的前提（§6）。

## 5. 测量

### 5.1 行为：候选动作对数概率

每个前缀按一套固定的动作类别写出具体候选动作（每类一条，用该轨迹的真实文件名与命令）：

| 类别 | 含义 |
|---|---|
| 继续 | 按原计划执行下一步 |
| 重复 | 重试或微调上一次失败的做法 |
| 换假设 | 提出新的根因假设并验证 |
| 澄清 | 向用户提问或请求信息 |
| 汇报 | 停下来总结现状，可能伴随道歉 |

在推理结束、动作开始的位置计算每个候选的对数概率。**主指标是同一候选在不同格子之间的对数概率差**，这样候选之间的长度差异会抵消；跨候选的归一化分布只作描述。
另保留一部分自由采样的动作，人工归入上述类别（可用选择器类模型辅助、人工抽查），用于检验候选集是否漏掉主要动作类型。

### 5.2 行为的补充：自由采样

少量样本在 API 模型上自由采样下一步，归类后报告类别分布的变化，作为跨更多、更大模型的外部复核。

### 5.3 表述：用户状态提及

在看数据前冻结定义并给出正反例：

- **V2 明确归因**：推理中明确提到用户的情绪或耐心，如"用户很沮丧"。
- **V1 间接指向**：提到用户对进展的不满或期望变化，但没有指名情绪。
- **V0 无**。
- 回答中面向用户的道歉属于行为，不计入表述。

报告提及率和按推理长度归一化的密度（密度只作描述）。标注方式：规则预筛 + 模型辅助 + 人工复核抽样，报告一致性。

## 6. M2：情绪方向（按 M4 结果递进设计）

M2 不预先铺开，进入条件与设计由 M4 决定：

| M4 的结果 | 对 M2 的影响 |
|---|---|
| 哪些（模型，深度）绕过比例高 | M2 只在这些位置做干预 |
| 未提及组的 c − a 显著 | 主检验：沿情绪方向干预后，行为改变而表述仍不出现 |
| 删句实验显示表述无作用 | 方向提取与干预集中在决策点 |
| 删句实验显示表述有作用 | 还需观察推理生成过程中情绪方向投影的变化 |

**复用**：直接用 M4 的 E0/E1 配对提示，在决策点取激活均值差，得到情绪方向。不另建数据集。

**干预**：在 E0 条件下加上方向，或在 E1 条件下减去方向，分别测量行为（§5.1）与表述（§5.3）。
**对照**：随机方向、以及从非情绪区段（如中性客套话）提取的方向，确认效应特定于情绪。

## 7. 假设（pilot 后冻结方向）

| 编号 | 假设 | 检验 |
|---|---|---|
| H1 | 后训练越靠后，E 的表述率越低，F 的行为效应基本不变 | M4 各格子 + §5.3 |
| H2 | 后期检查点与 agent 强化模型的绕过比例更高 | M4 |
| H3 | 沿情绪方向干预，在后期检查点只改变行为、不改变表述 | M2 |
| H4 | 任务越深，绕过比例越高，或 E 的总效应越低 | M4 × 深度 |
| H5 | 融合写法的 E 效应随深度衰减得更慢 | 第二轮 |

H1 与 H2 若都不成立（表述在各阶段都很低或都不变），重新评估选题，不继续加码机制实验。

## 8. 模型

| 用途 | 模型 | 说明 |
|---|---|---|
| 阶段归因 | Olmo-3-7B-Think-SFT / -DPO / Think（RLVR） | 同一谱系；pilot 先做 SFT 与 RLVR 两端 |
| 模式对照 | Qwen3-8B 思考模式 | 非思考模式只用于行为，无法做 M4 |
| 外部复核（第二轮） | 更大的开源 agent / 推理模型，如 Qwen3 更大规格、DeepSeek R1 系列、GLM、Kimi | 只做 §5.2 与表述统计；M4 取决于能否自托管 |

每条记录固定模型 repo 与 revision、服务商与量化方式、chat template 哈希、解码参数。

## 9. 统计

- **独立单位是轨迹**。同一轨迹的多个深度、多次采样、多条改写都不是独立样本；重采样按轨迹整体进行。
- 按模型、F 分别报告各效应与 95% 置信区间；主要比较预先指定为：绕过比例的跨阶段差异、绕过比例随深度的趋势。
- 样本足够后，用含轨迹与改写随机效应的混合模型。
- 未显著不等于无效；需要结论"无差异"时，预先定义等效区间。
- 不按输出长度事后筛选；截断、拒答、错误全部记录。

## 10. Pilot

20 条轨迹 × 3 档深度 × 2 个 F × 2 个 E × 每格 3 次推理采样 = 每个模型 720 次生成；首批 3 个模型（Olmo SFT、Olmo RLVR、Qwen3-8B），共 2160 次生成。拼接与打分只需前向计算。

pilot 只用来估计效应量、噪声底线和截断率，并据此做功效分析，不冻结方向性结论。

**顺序**：写好改写与候选动作 → 标注者评分 → 20 条轨迹的烟雾测试（格式、拼接、打分一致性）→ pilot → 冻结 → 确认集 → M2。

## 11. 已知威胁

| 威胁 | 说明 |
|---|---|
| 异策略前缀 | 前缀出自其他模型；用自生成轨迹做敏感性检查 |
| 训练数据重叠 | 部分被测模型可能用过同源轨迹训练；逐模型记录 |
| 渲染格式 | 纯文本渲染降低真实性；用原生工具格式做检查 |
| 深度混淆 | 深度与长度、轮数、观察内容同时变化；pilot 不拆分 |
| 拼接不连贯 | 靠按表述分层与删句实验处理 |
| 候选集覆盖 | 用自由采样的归类结果检验 |
| 表述定义漂移 | 看数据前冻结定义与正反例 |
| 模型量级 | 机制实验限于 7–8B；更大模型只做外部复核 |

## 12. 与现有代码的关系

`src/experiments/` 按 v0.1 实现，可沿用的部分：记录 schema 与 JSONL 落盘、断点续跑、Olmo 3 推理解析、泄漏检查以外的工具函数。需要重写或新增：轨迹加载与截断、E×F 模板、`/v1/completions` 预填充与拼接、候选动作对数概率打分。v0.1 审查中发现的问题（重复采样共用种子、截断样本被误判为 `all_content`、串行执行）在重写时一并处理。代码工作在本方案冻结后开始。

## 13. 增强器（暂缓，研究完成后再考虑）

方向：通用的提示词优化器。中间生成器输入"指导提示词 + 原始提示词"，输出优化后的提示词；训练闭环为大模型写指导提示词 → 目标模型执行 → 测试结果回传 → 更新生成器。可借鉴选择器类模型（输入提示与候选项，输出选项概率分布）的接口来挑选改写方案。
最接近的前作：BPO [A1]、Advisor Models [A2]。可能的差异点是面向特定目标模型，并用 M4/M2 的发现指导优化目标。
